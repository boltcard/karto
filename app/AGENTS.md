# Working in app/

This folder builds two apps from one Expo (React Native) project: Karto Wallet and Karto PoS, for Android and
iPhone. `variant.js` holds what differs between them; `APP_VARIANT=pos` chooses Karto PoS (the wallet when unset).
The repository's `README.md` says what the apps do.

## Expo changes: do not trust your memory of it

Expo ships breaking changes with every SDK release. Before writing code that touches an Expo or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Read the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, https://docs.expo.dev/llms.txt is an index of all the Expo docs.

## Commands

```sh
npm ci                      # install exactly what package-lock.json names
npm test                    # vitest: the unit tests (*.test.ts) and the screen tests (*.test.tsx)
npm run test:screens        # the screen tests alone
npm run typecheck           # tsc --noEmit
npx expo install <package>  # add a package at the version this Expo SDK wants; never npm install <package>
```

From the repository's root, `make test` runs the server's tests and these. Run it before calling a task done.

There is no linter. Do not run `npx expo lint`: it installs ESLint and edits `package.json`.

The project does not use EAS. Android builds go through `deploy/test/release-apk.sh` (`make phone-install`,
`make pos-install`; see `deploy/signing/README.md`), and iPhone builds through `.github/workflows/ios.yml`.

## Where things are

- `src/app/` holds Karto Wallet's screens and `src/pos-app/` Karto PoS's (Expo Router: every file there is a
  screen, `_layout.tsx` files define navigators). Keep everything else outside those two folders.
- `src/` otherwise is plain TypeScript by subject (`cardd/`, `lnvps/`, `onboarding/`, `wallet/`, `pos/` ...), tests
  beside the code they test. `src/testing/` holds the fakes the tests share.
- `modules/card-native/` is the apps' own native module: Kotlin in `android/`, Swift in `ios/` and `swift/`
  (NFC, SSH, the cameras, the device key, alerts).
- `plugins/` holds the config plugins that write native settings.
- `deploy-assets/` is generated by `make app-deploy-assets`: the server files the wallet uploads.
- `../testvectors/` holds vectors the Go and TypeScript tests both read: change one only together with both
  implementations.

## Rules

- `android/` and `ios/` are generated by `expo prebuild` and not committed. Never edit them by hand: change
  `app.json`, `variant.js` or a config plugin.
- `android/` is made for one app at a time. Delete it when changing between the wallet and the PoS.
- Colours and fonts live in `src/ui/theme.ts`. A test (`src/testing/sourceScan.test.ts`) fails on a colour or font
  written anywhere else.
- Karto PoS must not pull in the wallet's code: `src/pos/boundary.test.ts` walks the imports from its entry.
- The Google-free build must carry no Play Services code (`deploy/test/no-gms.sh` checks the APK). Check a new
  dependency for it.
- Pin exact versions for packages that are not Expo's own, as `package.json` does.
